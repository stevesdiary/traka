## Order statuses & lifecycle

| Status | Meaning |
| ------ | ------- |
| `PENDING` | Created, awaiting pickup / rider assignment |
| `IN_TRANSIT` | Rider picked up the package, en route |
| `OUT_FOR_DELIVERY` | Rider is at/near the delivery location |
| `DELIVERED` | Delivered and confirmed |
| `CANCELLED` | Cancelled (cannot be confirmed) |

```
PENDING ──► IN_TRANSIT ──► OUT_FOR_DELIVERY ──► DELIVERED
    │                                              ▲
    └──────────────── CANCELLED ───────────────────┘
```

- Recipient updates are only allowed in `PENDING` — see
  [Update recipient](/docs/orders/update-recipient).
- Confirming a `DELIVERED` order is idempotent; confirming a `CANCELLED` order
  returns `422`.

## Errors

| Status | Body | When |
| ------ | ---- | ---- |
| `404` | `{ "error": "Order not found" }` | Unknown number **or order belongs to another tenant** |
| `500` | `{ "error": "Failed to retrieve order" }` | Unexpected failure |

> Orders are tenant-scoped: you can only track orders created by your own
> business. Treat a `404` as "not found for this business".

## Live tracking

When a rider is assigned, `live_tracking` exposes `rider_location` and a
`websocket_channel` for real-time updates. Use `live_tracking_url` to link the
recipient to the public live-tracking page.
